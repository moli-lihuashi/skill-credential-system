# 基于联盟链的高校毕业生技能成果可信存证系统 — 系统设计

> 本文档同时作为毕业设计论文的「需求分析 / 系统设计」章节素材。
> 题目：基于联盟链的高校毕业生技能成果可信存证系统
> 技术栈：Solidity + Golang + Vue3 + MySQL + IPFS(可选) + Linux CentOS7

---

## 1. 系统目标

针对高校学生实训报告、技能证书、竞赛获奖、项目实践成果容易伪造、纸质证书核验繁琐、企业招聘难以快速辨别真伪的痛点，搭建面向职业院校的**联盟链可信存证平台**：

| 参与方 | 职责 |
|---|---|
| 学校（院校管理员） | 联盟链授权节点，录入技能证书、竞赛获奖，成果上链 |
| 实训企业 | 联盟链授权节点，录入岗位实训评价、实训项目成果 |
| 学生 | 查看本人全部链上存证凭证、存证历史 |
| 招聘企业 | 凭存证编号 + 学生信息进行真实性核验 |

核心机制：
1. 原始文件存 IPFS/MySQL，**链上只存哈希与凭证元数据**，保护隐私
2. 合约返回**唯一存证凭证编号**
3. 链上历史**不可删除修改**（仅可新增）
4. 全部操作日志哈希上链留痕

## 4. 系统架构

### 4.1 总体架构（四层）

```
┌────────────────────────────────────────────────────────────────┐
│  展示层 (Vue3)                                                  │
│  学生端 │ 院校管理端 │ 实训企业端 │ 招聘企业核验端                   │
└──────────────────────────┬─────────────────────────────────────┘
                           │ HTTP / JSON (JWT 鉴权)
┌──────────────────────────┴─────────────────────────────────────┐
│  业务层 (Golang)                                                │
│  账号权限 │ 成果管理 │ 存证服务 │ 核验服务 │ 日志服务 │ 文件服务     │
└───────┬──────────────────────────────┬─────────────────────────┘
        │ ethclient / ABI 绑定          │ SQL
┌───────┴──────────────┐    ┌──────────┴─────────┐  ┌───────────┐
│  联盟链层 (Solidity)  │    │  数据层 (MySQL)     │  │ IPFS(可选)│
│  成果存证合约         │    │  用户/成果/凭证/日志  │  │ 附件文件   │
│  凭证核验合约         │    └────────────────────┘  └───────────┘
└──────────────────────┘
        ▲
        │ 节点共识（授权节点：学校 + 实训企业）
   联盟链网络（开发/演示：本地私链 Ganache；部署：CentOS7 私链节点）
```

### 4.2 链上 / 链下数据划分

| 数据 | 存储位置 | 原因 |
|---|---|---|
| 文件哈希、学生ID哈希、成果类型、时间戳、存证编号、核验状态 | **链上** | 不可篡改、可公开验证 |
| 学生姓名、学号、联系方式 | MySQL | 隐私保护 |
| 实训报告扫描件、证书扫描件 | IPFS / 文件服务器 | 体积大 |
| 操作日志 | MySQL + 日志摘要哈希上链 | 可审计、防抵赖 |

## 6. 智能合约设计

### 6.1 合约接口 CredentialRegistry

```solidity
function registerStudent(string studentId) → 生成链身份
function storeCredential(string credentialNo, string studentId, string achType, string fileHash) → 上链存证
function verifyCredential(string credentialNo, string fileHash) → (bool passed, ...元数据)
function getCredential(string credentialNo) → 只读查询
function logOperation(string opHash) → 操作日志上链
```

### 6.2 存证结构（链上）

```solidity
struct Credential {
    string credentialNo;   // 唯一存证编号
    string studentId;      // 学生 ID（或其哈希）
    string achievementType;// 成果类型
    string fileHash;       // 文件 SHA-256
    uint256 timestamp;     // 上链时间戳
    address issuer;        // 上链节点（学校/实训企业）
    bool exists;           // 是否已存在（防重放）
}
```

### 6.3 核验逻辑

```
输入: credentialNo + fileHash(重新计算)
链上比对: stored.fileHash == input.fileHash
输出: 核验通过(数据未篡改) / 核验不通过(信息存在篡改风险)
```

## 9. 创意功能：凭证二维码（加分项）

### 9.1 功能说明

在完成任务书基本功能的基础上，本系统增加**存证凭证二维码**创意功能：

- 学生在「我的存证」页面可对每个凭证生成**核验二维码**
- 企业招聘人员**扫码**即可自动跳转到核验页，并**预填存证编号与文件哈希**
- 点击「一键核验」即可得到「核验通过 / 核验不通过」结果
- 同时支持**一键复制存证编号**，方便电话/邮件核验

### 9.2 业务价值

| 角色 | 使用场景 |
|---|---|
| 学生 | 面试时展示手机二维码，面试官扫码即时核验，替代纸质证书 |
| 招聘企业 | 扫码免手动输入，降低核验操作门槛 |
| 院校 | 提升成果认证的现代化、便捷化水平 |

### 9.3 技术实现

- 后端：`GET /api/credential/:no/qrcode` 返回凭证 JSON + base64 编码内容
- 前端：Canvas 绘制二维码风格标识图（可替换为标准 qrcode 库）
- 核验页：`/verify?credential_no=xxx&file_hash=yyy` 自动预填，onMounted 读取 query 参数
